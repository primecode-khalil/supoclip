# Proxy Implementation Plan

> **For agentic workers:** Implement inline in tested increments. The owner has
> authorized implementation; routine technical decisions are ours. Use the
> existing isolated checkout and do not create another checkout or delegate
> implementation. The brainstorming skill's fresh builder check found nothing
> important left unanswered.

**Goal:** A separate Proxy dashboard with saved connections, purpose selection,
priority and bounded automatic failover for YouTube ingestion.

**Architecture:** PostgreSQL stores encrypted configuration; a refreshed immutable
snapshot serves synchronous download code. Redis shares short-lived health.
Existing source budgets/caches and recorder recovery retain media. A loopback
CONNECT adapter keeps live ffmpeg traffic on credentialed/SOCKS routes.

**Tech Stack:** Existing FastAPI, SQLAlchemy, Redis, yt-dlp, standard-library
sockets, Next.js, pytest, Vitest and Playwright. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-20-proxy-design.md`

## Global constraints

- Preserve the paired Mac, encrypted AI/social settings, captures and approved
  YouTube upload receipts. Existing single-Mac pairing remains supported.
- UI says **Proxy**, **Live streams**, **Video imports**, **Both**. URL imports
  are distinct from local file uploads and official social publishing.
- Cap ten URL connections plus the existing Mac; each URL is write-only.
- No direct/paid-download fallback for a purpose assigned to managed proxies.
- Keep overall time/byte bounds, source caches and A/V timestamp flags.
- Preserve locks/base pins. Reuse encrypted app-settings storage, update changelog, use demo
  media, scan final images and drain finite jobs before restarting production.

## Review focus

1. Removed/disabled/edited connections cannot return through legacy environment
   settings or a stale health key; running work may finish on its held route.
2. A bot challenge differs from offline/private media; only transport/access
   failures cause a shared cooldown.
3. Signed URLs, partial files and sticky sessions cannot cross route attempts.
4. Proxy credentials never appear in API reads, error validation or child argv.
5. Unknown health/Redis loss never enables an unassigned direct connection.
