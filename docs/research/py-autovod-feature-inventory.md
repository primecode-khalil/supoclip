# py-autovod: complete feature-preservation inventory

Static audit, 15 November 2026, of `0jc1/py-autovod` at **`424f49815aba773c85cc8a7851ac52c6554dfa96`**. All 13 `src/` files, both INI templates, tests, packaging, scripts and CI were inspected. No capture, model inference, upload or deployment was run. “Implemented” means executable code exists; it does not establish platform compatibility or runtime reliability. Suggested owners below are proposed merged-product components, using SupoClip’s existing application/database/worker foundation.

The preservation requirement is **archives plus clips plus automation plus CLI**. Replacing AutoVOD with only a live-to-clips adapter would lose useful behavior. Keep selectable providers and archive workflows under one asset/job model; remove duplicate orchestration after migration.

## Features and proposed ownership

**AV-01 — CLI and startup.** Console entry point is `autovod = main:main`; `python src/main.py` also works from the repository context. Flags are `-n/--name` for one streamer, `-v/--version`, and argparse’s `-h/--help`. Otherwise the configured list is monitored. Version comes from CWD `pyproject.toml`, falling back to `0.0.0`; `recordings/` is created even for `--version`. Imports load settings, heavy transcription dependencies, a running processor singleton, and potentially restored uploads **before argument parsing**. Preserve a CLI over shared services, with explicit initialization and side-effect-free help/version. [Main](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/main.py#L6-L55), [entry point](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/pyproject.toml#L75-L76).

**AV-02 — Configuration and secrets.** `settings.py` loads dotenv, `OPEN_ROUTER_KEY`, and CWD `config.ini` at import. Missing API key disables automatic Clipception globally. Each lowercased streamer uses `<name>.ini` **as a complete replacement**, falling back to `default.ini` only when absent; even an empty existing file prevents fallback. There is no option-level inheritance from default or global config. Partial streamer files can raise missing-section/option exceptions. Standard ConfigParser interpolation applies. Preserve an INI importer, channel overrides and environment secrets; introduce validated explicit inheritance with migration notices. [Settings](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/settings.py), [loader](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/utils.py#L156-L166), [selection](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/stream_monitor.py#L21-L56).

**AV-03 — Multi-channel monitoring.** Comma-separated streamer names are stripped, empty entries removed and exact duplicates discarded using a set, losing order; case variants can still create duplicate lowercased monitors. One daemon thread per channel checks `streamlink <url>`, then records; all checks/captures are followed by the global retry delay. Source enum/URL mappings include Twitch, Kick, YouTube `@handle/live`, DLive and Rumble; mappings alone do not verify plugin support. Preserve a channel/session service with platform-specific health and normalized identities. [Manager](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/stream_manager.py#L32-L72), [platforms](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/utils.py#L12-L72).

**AV-04 — Recording and quality.** Recorder executes `streamlink -o <path> <url> <quality>`; quality strings, including comma-separated fallback lists, are passed intact. Additional flags are split **on commas**, with each resulting string becoming one argv element; space-separated flag/value text is not shell-tokenized. Default flag is `--twitch-disable-ads`. YouTube first tries `yt-dlp --get-url -f best` with a 60-second timeout, then falls back to the channel URL; the preceding Streamlink live check can prevent reaching this workaround. Recording blocks until exit, and only exit zero plus an existing file returns a processing path. Preserve supervised capture and quality controls; recover usable partial recordings, reconnect and expose gaps. [Recorder](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/stream_monitor.py#L58-L179).

**AV-05 — Metadata and output identity.** `streamlink --json` is attempted up to five times until title or ID is nonempty; actual inter-attempt sleeps are 4/8/16/32 seconds. Output is `recordings/<streamer>/<id-or-local-timestamp>/<title>-<streamer>-<DD-MM-YYYY-HH-MM-SS>.ts`. The suffix does not enforce container type. Metadata is held in memory, not saved as a sidecar; title/ID are not sanitized. Preserve stream identity, human-readable names and timestamp fallback in the asset library, with safe paths and durable metadata. [Metadata](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/utils.py#L88-L128), [naming](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/stream_monitor.py#L85-L93).

**AV-06 — Worker lifecycle.** SIGINT/SIGTERM stop monitors, terminate the current recorder, kill after two seconds, and stop/persist the uploader. Monitor joins allow only 0.02 seconds; sleeps are not interruptible. Manager never calls processor shutdown/drain. Empty streamer lists leave `running=true`. Processing is one daemon worker with an unbounded memory queue and no durable restart recovery; failures outside narrow catches can kill it. Move job state to database-backed orchestration and retain orderly stop/drain behavior. [Lifecycle](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/stream_manager.py#L19-L30), [stop](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/stream_manager.py#L74-L92), [processor](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/processor.py#L22-L106).

**AV-07 — Full-VOD remux and re-encode.** Every queued recording is remuxed to same-basename `.mp4` using `ffmpeg -i input -c copy output -loglevel error`; status is ignored. Optional re-encoding produces `.reencoded.mp4`, selecting video codec/CRF/preset/log level and copying audio. Defaults are libx265/25/medium/error. There is no overwrite flag, codec-specific argument adaptation, arbitrary extra arguments, extension selection or validation of the remux output. Preserve archive rendition jobs separately from clip rendering, checking outputs before downstream work. [Commands](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/processor.py#L123-L183).

**AV-08 — Local ASR providers.** Audio extraction makes same-basename 16 kHz mono PCM-S16LE WAV. Providers are original Whisper and faster-whisper, with configured model/device/language, CUDA initialization test and CPU fallback. Faster-whisper chooses float16 on CUDA, float32 otherwise, optionally wrapping `BatchedInferencePipeline` and passing batch size. Models load per video; CUDA cache is cleared afterward. Neither provider requests word timestamps. Preserve both as transcription providers, retaining batching and adding word timing for SupoClip captions. [ASR](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/transcription.py#L112-L139), [decoding](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/transcription.py#L188-L215), [models/device](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/transcription.py#L258-L327).

**AV-09 — Audio enrichment and grouping.** Each ASR segment receives 8 kHz RMS, zero-crossing rate, spectral centroid, volume label and intensity label. Consecutive segments are combined until elapsed start-to-end reaches `clip_duration`, retaining the short final remainder; feature values are averaged without duration weighting. This is a minimum candidate grouping span, not a hard exported-clip duration. Results become `<basename>.enhanced_transcription.json` with start/end/text/features. PCM samples are unnormalized against 0.1/0.3 volume thresholds, making labels suspect. Preserve optional audio enrichment in the common transcript schema after calibration. [Features/grouping](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/transcription.py#L71-L109), [aggregation](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/transcription.py#L142-L255).

**AV-10 — LLM highlight selection.** OpenRouter’s OpenAI-compatible client sends transcript/features, requests JSON, and uses configurable model/temperature/token limit. Prompt allows combining candidates and asks for title/start/end/1–10 score/factors/recommended platforms, with 30% audio and 70% content weights. These are prompt instructions, not numerical scoring. Requests retry four times with 2/4/8-second waits. Candidate batches run in a ThreadPoolExecutor sized to CPU count; the normal path batches ten candidates. Invalid/failed batches can silently contribute no clips. Preserve a selectable analysis strategy with bounded API concurrency, provenance and explicit failures. [Prompt/retries](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/gen_clip.py#L33-L115), [parallel ranking](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/gen_clip.py#L118-L147).

**AV-11 — Candidate artifacts and clean clips.** Parser strips JSON fences and checks key presence only; timestamps, types, bounds, duration and overlap are unvalidated. Scores sort descending; top N become `top_clips_one.json` with total count and timestamp. Extraction uses `ffmpeg -y -ss start -to end -i source -c:v libx264 -c:a aac`, with sanitized title filenames in `clips/`. No captions are burned in. Repeated names/files overwrite. Minimum-score filtering exists as a function parameter but automatic processing hardcodes zero. Preserve scored selection artifacts and optional clean landscape renders with stable clip IDs. [Selection](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/gen_clip.py#L150-L209), [extraction](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/gen_clip.py#L236-L330).

**AV-12 — Shorts rendition.** Optional second pass produces `_shorts.mp4`: scale to fit 1080×1920, black padding, square pixels, H.264/AAC. It retains the landscape clip and does no face tracking/cropping or subtitles. Shorts failure still reports the landscape extraction successful. Only global `shorts_format` is read. Preserve this fit/pad preset alongside SupoClip’s other layouts, with independent rendition status. [Shorts](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/gen_clip.py#L212-L281), [global selection](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/processor.py#L185-L255).

**AV-13 — Standalone file workflows.** `python src/process_vid.py [video_path]` validates existence and directly transcribes/selects/extracts, bypassing the global automatic-enabled gate and upload. `python src/download_yt.py URL -o/--output downloads -f/--format best` validates HTTP(S), uses yt-dlp, restricted title filenames and MP4 merge. Its format argument is ignored in favor of a hardcoded best-MP4 selector; `extractor-arg` is supplied as written, without verifying that API option. Preserve local-file and URL ingest plus CLI compatibility; make format selection effective. [File tool](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/process_vid.py), [download tool](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/download_yt.py#L29-L89).

**AV-14 — Full-VOD destinations and credentials.** Automatic upload targets the converted/re-encoded **full recording**, never generated clips. YouTube delegates only `-filename` to `/root/youtubeuploader/youtubeuploader`, Windows `C:\youtubeuploader\youtubeuploader.exe`, or same-basename executable in CWD. Credentials/configuration belong to that external binary; AutoVOD sets no credential path, OAuth or metadata flags. Rclone executes `rclone copy file remote:directory`, inheriting the external tool’s credential configuration. Preserve archive destinations; extend SupoClip’s clip-specific publishing model to full-VOD assets and retain rclone as an archive-transfer provider. [Destinations](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/uploader.py#L12-L75), [queued asset](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/processor.py#L76-L86).

**AV-15 — Upload queue and retries.** Separate singleton daemon worker snapshots pending jobs to `recordings/upload_queue.json` via temporary file/replace, restores at import, skips missing files, and retries with configurable total attempts (default five), 2/4/8/16-second waits, and preserved attempt counts. It stores destination, retention flags and source path, but no publication ID/idempotency key. In-flight jobs are absent from snapshots; concurrent persistence uses one temporary path and its lock does not cover writes. Move these semantics into durable archive/publication jobs with reconciliation. [Queue](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/uploader.py#L78-L274), [persistence](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/uploader.py#L315-L375).

**AV-16 — Retention.** With upload off, `save_locally=false` deletes raw and selected full-VOD output after processing. Successful uploads delete them under that same setting. Exhausted uploads retain files if either `save_on_fail` or `save_locally` is true. Clips/transcription/WAV remain; re-encoding leaves the intermediate MP4 undeleted. WAV paths accumulate in a cleanup list but are never cleaned. Preserve policy intent through artifact/dependency-aware retention, independently covering originals, archive renditions, clips, intermediates and retry inputs. [Local cleanup](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/processor.py#L87-L121), [upload cleanup](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/uploader.py#L276-L313).

**AV-17 — Logging and progress.** Loguru emits colored stderr; debug is hardcoded on and optional rotating `app.log` is hardcoded off. The debug filter compares lowercase `debug` against uppercase level names. Tqdm displays nonnegative directory-size growth, including derived artifacts, rather than actual network throughput. Recorder stderr and most command output are discarded; `run_command` replaces failed subprocess results with status −1, losing diagnostics. Preserve CLI progress, while adding session/job logs and reliable error results. [Logger](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/logger.py), [progress](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/stream_manager.py#L97-L124), [helper](https://github.com/0jc1/py-autovod/blob/424f49815aba773c85cc8a7851ac52c6554dfa96/src/utils.py#L31-L49).
