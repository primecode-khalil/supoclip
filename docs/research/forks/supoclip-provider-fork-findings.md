# SupoClip provider, GPU, local-processing and social fork audit

Research date: 2026-11-16. Upstream API `commits/main` resolved to `e42e93b02873d29e2000a6a8235c10e23f8c99c9` during this audit. This is targeted source inspection supporting the separate exhaustive fork/branch inventory; it does not claim every fork was executed. Repository descriptions, stars and READMEs were discovery signals only. Implementations below were checked at the recorded commits. No software was installed, implemented, deployed or published.

## Decision

Keep current upstream as the integration base. The most useful bounded donors are **Obiorachibuike's modular CPU/CUDA faster-whisper engine**, **FloMotion33's smaller CPU-only adapter**, **Sh8ders' native MLX adapter**, and **Zeidev's OpenAI-compatible LLM/GPU configuration**. **stale2000** contains an actual NVIDIA video-encoding implementation, but its old MoviePy architecture and deployment configuration need substantial adaptation. **tsfarizi** supplies a separate Qwen3-ASR service with forced alignment, useful if a remote GPU speech service is wanted. None of these inspected candidates supplies Facebook publishing or the requested live-session capture/archive controller.

## What current upstream already supplies

- Local OpenAI Whisper with word timestamps, the standard transcript cache, and YouTube-caption ingestion are already implemented. A fork advertising only local Whisper is not adding this capability. The current dispatch accepts Whisper and YouTube captions and otherwise uses AssemblyAI. [Immutable transcription source](https://github.com/FujiwaraChoki/supoclip/blob/e42e93b02873d29e2000a6a8235c10e23f8c99c9/backend/src/media/transcription.py#L177-L205), [dispatch](https://github.com/FujiwaraChoki/supoclip/blob/e42e93b02873d29e2000a6a8235c10e23f8c99c9/backend/src/media/transcription.py#L324-L348).
- Ollama is already supported; another Ollama README is not a reason to replace upstream. [Model construction](https://github.com/FujiwaraChoki/supoclip/blob/e42e93b02873d29e2000a6a8235c10e23f8c99c9/backend/src/ai.py).
- YouTube/TikTok/Instagram publishing is already registered upstream. There is no Facebook provider in this registry. Branches called `feat/social-publishing` or `codex/multi-account-publishing` often preserve upstream development history rather than add a distinct fork feature. [Current registry](https://github.com/FujiwaraChoki/supoclip/blob/e42e93b02873d29e2000a6a8235c10e23f8c99c9/backend/src/social/registry.py#L10-L24).
- The maintainer explicitly distinguishes implemented basic local Whisper from the unmerged faster-whisper/WhisperX extensions; old comments saying these extensions shipped are superseded by the maintainer's clarification. [Issue 40](https://github.com/FujiwaraChoki/supoclip/issues/40), [open PR 53](https://github.com/FujiwaraChoki/supoclip/pull/53), [closed, unmerged PR 95](https://github.com/FujiwaraChoki/supoclip/pull/95).

### Obiorachibuike: most complete inspected modular faster-whisper donor

The feature branch `arena/72cd2c27-supoclip` at `47b1b89f29d50e298dce525f5e1bcdd0d984e12a` was merged into the fork's main at `49ddba2ee829f4b5960484ee98c67ffbea1411cf`. The exhaustive comparison records 42 changed files and 158 upstream commits missing from this branch; this remains a donor rather than a replacement base. The underlying feature commit is [`57d3417a88c036a269ab8b4d526c44b08ebb0d71`](https://github.com/Obiorachibuike/supoclip/commit/57d3417a88c036a269ab8b4d526c44b08ebb0d71).

The separate 398-line engine probes CTranslate2 for CUDA, caches models under a lock by model/device/compute/download-root, retries CUDA **model-load** failures on CPU int8, and requests actual word timestamps with configurable VAD and beam size. It also catches errors during lazy decoding and derives sentence-sized lines for analysis while retaining raw word/segment data for captions. A decode failure becomes an explicit error; it does not automatically retry inference on CPU after a successfully loaded CUDA model later fails. [Model selection/cache/fallback](https://github.com/Obiorachibuike/supoclip/blob/49ddba2ee829f4b5960484ee98c67ffbea1411cf/backend/src/media/faster_whisper_engine.py#L81-L207), [inference/word adapter](https://github.com/Obiorachibuike/supoclip/blob/49ddba2ee829f4b5960484ee98c67ffbea1411cf/backend/src/media/faster_whisper_engine.py#L218-L337), [analysis grouping](https://github.com/Obiorachibuike/supoclip/blob/49ddba2ee829f4b5960484ee98c67ffbea1411cf/backend/src/media/faster_whisper_engine.py#L340-L398).

The adapter is wired into current-style transcription dispatch/cache, and the added tests cover fake GPU availability, CUDA model-load failure, real-shaped word timing/cache normalization, silence, missing dependencies and dispatch. These are mocked unit contracts, not a GPU inference benchmark. [Integration](https://github.com/Obiorachibuike/supoclip/blob/49ddba2ee829f4b5960484ee98c67ffbea1411cf/backend/src/media/transcription.py#L334-L390), [tests present](https://github.com/Obiorachibuike/supoclip/blob/49ddba2ee829f4b5960484ee98c67ffbea1411cf/backend/tests/unit/test_faster_whisper.py).

Two deployment gaps need to be fixed during any port: `pyproject.toml` adds faster-whisper, but the committed `uv.lock` contains no faster-whisper/CTranslate2 package entries while Docker installs using `uv sync --frozen`; the locked image path therefore cannot be assumed to contain the declared new engine. Its Compose file also supplies model/device settings without any NVIDIA device reservation. Regenerate the dependency lock and validate an actual container inference path with deliberate GPU exposure. This conclusion follows from static file consistency; no container build was run. [Dependency declaration](https://github.com/Obiorachibuike/supoclip/blob/49ddba2ee829f4b5960484ee98c67ffbea1411cf/backend/pyproject.toml), [lock](https://github.com/Obiorachibuike/supoclip/blob/49ddba2ee829f4b5960484ee98c67ffbea1411cf/backend/uv.lock), [Dockerfile](https://github.com/Obiorachibuike/supoclip/blob/49ddba2ee829f4b5960484ee98c67ffbea1411cf/backend/Dockerfile#L31-L43), [Compose](https://github.com/Obiorachibuike/supoclip/blob/49ddba2ee829f4b5960484ee98c67ffbea1411cf/docker-compose.yml).

Its `/settings/ai` screen is a real read-only status UI backed by authenticated `/ai/providers`; it displays selected models, cost-policy labels, warnings and reported usage. Provider changes remain environment/admin configuration. Usage counters are per process, so the API cannot present a durable combined total from all workers without aggregation. The wider branch also introduces Agnes-specific providers and default cost policy; those product choices are separable from the local speech engine and were not independently validated as a free hosted service. [API](https://github.com/Obiorachibuike/supoclip/blob/49ddba2ee829f4b5960484ee98c67ffbea1411cf/backend/src/api/routes/ai_providers.py), [UI](https://github.com/Obiorachibuike/supoclip/blob/49ddba2ee829f4b5960484ee98c67ffbea1411cf/frontend/src/app/settings/ai/page.tsx), [usage scope](https://github.com/Obiorachibuike/supoclip/blob/49ddba2ee829f4b5960484ee98c67ffbea1411cf/backend/src/ai_usage.py#L1-L10).

### FloMotion33: closest fit for a small provider port

The fork's `main` is unchanged upstream `d8b500a0e36455986c077863fdf8cbb2fde884bd`. The feature exists only on the named branch, exactly three commits ahead of that base, touching 14 files overall. [Compare](https://github.com/FloMotion33/supoclip/compare/d8b500a0e36455986c077863fdf8cbb2fde884bd...778dc43ac09bba40fb1fc97f4fa0ab234f820782).

The first commit, [`2c73713ad56ae2eb96953ec37f0866077f8c3048`](https://github.com/FloMotion33/supoclip/commit/2c73713ad56ae2eb96953ec37f0866077f8c3048), adds the provider. The loader explicitly selects `device="cpu", compute_type="int8", cpu_threads=0`, caches models by name and converts segment/word timestamps into the same shape as upstream Whisper. It is **not GPU inference**, despite the broader faster-whisper/GPU search category. No speed or accuracy claim was independently benchmarked. [Adapter](https://github.com/FloMotion33/supoclip/blob/778dc43ac09bba40fb1fc97f4fa0ab234f820782/backend/src/media/transcription.py#L208-L280), [provider tests present](https://github.com/FloMotion33/supoclip/blob/778dc43ac09bba40fb1fc97f4fa0ab234f820782/backend/tests/unit/test_faster_whisper.py).

Its caption commit ends groups at sentence punctuation in both render and editor-preview paths. This is relevant to polished captions: a fixed-size caption group can otherwise show the beginning of the next sentence too early. It is a separate improvement worth a render/preview comparison, not evidence of a complete new caption engine. [Caption grouping](https://github.com/FloMotion33/supoclip/blob/778dc43ac09bba40fb1fc97f4fa0ab234f820782/backend/src/media/captions.py#L528-L549), [preview parity](https://github.com/FloMotion33/supoclip/blob/778dc43ac09bba40fb1fc97f4fa0ab234f820782/frontend/src/lib/editor/document.ts#L260-L281).

### Sh8ders: useful Apple Silicon support hidden on a nondefault branch

`claude-native` is nine commits / 44 files ahead of fork main, including a large extraction of clip-selection logic and prompts. The added native CLI exposes prepare/schema/validate/render and editing workflows that reuse the media pipeline. This is a different interaction model from the existing web product. [Branch compare](https://github.com/Sh8ders/claudeclip/compare/main...6dcef5e2f58e1233c08d1e035f4f3ea189f3d1f1), [CLI](https://github.com/Sh8ders/claudeclip/blob/6dcef5e2f58e1233c08d1e035f4f3ea189f3d1f1/backend/src/native/cli.py).

The useful provider slice is concrete: `WHISPER_BACKEND=openai|faster|mlx|auto`; auto prefers MLX only on Darwin ARM64 with the module available, then faster-whisper, then OpenAI Whisper. Faster-whisper uses auto device selection and configurable compute type. MLX Whisper requests word timestamps and normalizes NumPy timing values before caching. Optional dependency extras separate native faster-whisper from Apple-only MLX. [Backend selection and adapters](https://github.com/Sh8ders/claudeclip/blob/6dcef5e2f58e1233c08d1e035f4f3ea189f3d1f1/backend/src/media/transcription.py#L205-L357), [dependency extras](https://github.com/Sh8ders/claudeclip/blob/6dcef5e2f58e1233c08d1e035f4f3ea189f3d1f1/backend/pyproject.toml#L39-L45).

This can inform a native Apple worker or external local transcription service. It does not make Linux Docker use the Apple GPU. The inspected social provider directory retains the upstream platforms and adds no Facebook provider. [Registry](https://github.com/Sh8ders/claudeclip/blob/6dcef5e2f58e1233c08d1e035f4f3ea189f3d1f1/backend/src/social/registry.py).

### Zeidev: recent configurable gateway, GPU opt-in and subtitle import

Open [PR 361](https://github.com/FujiwaraChoki/supoclip/pull/361) is unmerged, with 33 changed files / 1,439 additions / 41 deletions. Actual `LLM=custom:*` construction uses `OpenAIChatModel` and `OpenAIProvider` with the configured base URL/key; it is a text-model gateway, not an audio provider. [Model implementation](https://github.com/Zeidev/supoclip/blob/9a3aabb7efcacaedded0e5c2f5e4253c777e3301/backend/src/ai.py#L570-L579).

Its GPU override exposes NVIDIA devices to the worker; the Dockerfile can replace the locked Torch wheel with a specified version/index to cover older GPU architectures. It retains upstream OpenAI Whisper's device auto-selection, rather than add faster-whisper or NVENC. The override comment requires `BACKEND_CPU_ONLY=false`; the main template can otherwise select CPU wheels. The optional post-lock Torch replacement also needs deliberate image/dependency validation before reuse. [Compose override](https://github.com/Zeidev/supoclip/blob/9a3aabb7efcacaedded0e5c2f5e4253c777e3301/docker-compose.gpu.yml), [Dockerfile](https://github.com/Zeidev/supoclip/blob/9a3aabb7efcacaedded0e5c2f5e4253c777e3301/backend/Dockerfile#L34-L51).

The SRT path is useful for edited transcripts, but distributes words within cue windows; these are not measured ASR word boundaries. It also writes an SRT upload under local temporary storage and explicitly does not implement object-storage mirroring, which matters for current upstream's independent render worker architecture. For professional word-synced captions, retain ASR/forced alignment or add an alignment step for imported subtitle text. [Cue-to-word construction](https://github.com/Zeidev/supoclip/blob/9a3aabb7efcacaedded0e5c2f5e4253c777e3301/backend/src/media/srt_transcript.py#L109-L173), [upload ownership/storage code](https://github.com/Zeidev/supoclip/blob/9a3aabb7efcacaedded0e5c2f5e4253c777e3301/backend/src/srt_uploads.py), [author's scope and verification claims](https://github.com/FujiwaraChoki/supoclip/pull/361).

### stale2000: a real NVENC implementation, with limitations

The encoder settings choose `h264_nvenc` when GPU encoding is enabled, CPU encoding is not forced and `ffmpeg -encoders` lists NVENC; otherwise they choose libx264. The probe itself warns that encoder enumeration does not prove a usable runtime in Docker/WSL2. No successful GPU encode was independently run. [Selection and probe](https://github.com/stale2000/supoclip/blob/6405d91ef562fec6daf5f6c9f55d07d47dd1ae8e/backend/src/video_utils.py#L34-L139).

The branch sets MoviePy to system FFmpeg, uses an NVIDIA-enabled FFmpeg image, copies CUDA runtime libraries and reserves GPU devices in Compose. Its faster-whisper transcription chooses CUDA float16 when CTranslate2 reports a GPU, otherwise CPU int8, and writes actual word timings when available. The old word-cache schema omits current utterance/version fields. [Container build](https://github.com/stale2000/supoclip/blob/6405d91ef562fec6daf5f6c9f55d07d47dd1ae8e/backend/Dockerfile), [transcription](https://github.com/stale2000/supoclip/blob/6405d91ef562fec6daf5f6c9f55d07d47dd1ae8e/backend/src/video_utils.py#L1562-L1643).

Reusing this means implementing a codec policy in the current FFmpeg helpers, validating an actual tiny encode, and deciding which operations remain CPU filters. This branch does not establish full GPU decoding, subtitle compositing or end-to-end GPU rendering.

### tsfarizi: Qwen3-ASR service, rather than another Whisper variant

The separate `asr/` application loads `Qwen/Qwen3-ASR-1.7B` plus `Qwen/Qwen3-ForcedAligner-0.6B`, requires CUDA in real mode, requests timestamp output and converts alignment seconds to milliseconds. Fake-model mode exists for transport/contract tests and must not be confused with successful model inference. [Model lifecycle/inference](https://github.com/tsfarizi/supoclip/blob/054da1a782570d54340c5f3f752badb7c3b5fdaa/asr/src/model.py#L37-L131), [defaults](https://github.com/tsfarizi/supoclip/blob/054da1a782570d54340c5f3f752badb7c3b5fdaa/asr/src/config.py), [GPU dependencies](https://github.com/tsfarizi/supoclip/blob/054da1a782570d54340c5f3f752badb7c3b5fdaa/asr/pyproject.toml).

A serial inference queue limits concurrent model access. The backend posts audio to `/v1/transcribe`, retries server/transport failures and caches returned words. Missing alignment degrades captions to hook-only output with a warning. It uses the older `TRANSCRIPT_PROVIDER=local_asr` naming and a custom response contract, so it is a separate-service donor requiring adaptation to the current provider interface. [Service](https://github.com/tsfarizi/supoclip/blob/054da1a782570d54340c5f3f752badb7c3b5fdaa/asr/src/main.py#L44-L71), [backend adapter](https://github.com/tsfarizi/supoclip/blob/054da1a782570d54340c5f3f752badb7c3b5fdaa/backend/src/video_utils.py#L317-L390).

## Older provider PRs: real code, high merge cost

**oxbar**, `feat/backend-faster-whisper-transcription`, [`5e102cff9bd3622fa1e8c384a5af380a0b7587f2`](https://github.com/oxbar/supoclip/tree/5e102cff9bd3622fa1e8c384a5af380a0b7587f2), is open [PR 53](https://github.com/FujiwaraChoki/supoclip/pull/53). It implements model caching, explicit device/compute/language configuration, real word timestamps and admin runtime settings. This is a useful configuration reference; its June-era `video_utils.py` monolith and `TRANSCRIPT_PROVIDER` key differ from today's modular code and `TRANSCRIPTION_PROVIDER`. [Loader](https://github.com/oxbar/supoclip/blob/5e102cff9bd3622fa1e8c384a5af380a0b7587f2/backend/src/video_utils.py#L218-L230), [transcribe/normalize](https://github.com/oxbar/supoclip/blob/5e102cff9bd3622fa1e8c384a5af380a0b7587f2/backend/src/video_utils.py#L323-L347).

**skmdfardin**, former `feat/stage-progress-and-gpu-transcription`, is closed and unmerged [PR 95](https://github.com/FujiwaraChoki/supoclip/pull/95), preserved at upstream pull ref / commit `f467ff31e395f4b38c7810bc47bdd33e46313c39`. The fork clone URL was unavailable, but `refs/pull/95/head` was fetched successfully. It really implements faster-whisper with checkpoint/resume, WhisperX alignment, OpenAI-compatible audio requests, fallback chaining and NVIDIA Compose reservations. It touches 51 files with a large monolithic media rewrite; wholesale merge cost is high. [Local providers](https://github.com/FujiwaraChoki/supoclip/blob/f467ff31e395f4b38c7810bc47bdd33e46313c39/backend/src/video_utils.py#L986-L1335), [GPU override](https://github.com/FujiwaraChoki/supoclip/blob/f467ff31e395f4b38c7810bc47bdd33e46313c39/docker-compose.gpu.yml).

A significant caption-quality limitation is visible in the remote audio path: it requests **segment** timestamp granularity, and when word timings are absent it fabricates equal word intervals from segments or even a default total duration. Its advertised compatibility does not prove professional word synchronization. Also the CUDA fallback around `model.transcribe()` does not cover the later lazy segment iteration where decoding errors may occur. These are code-level integration concerns, not failures reproduced in this audit. [Request options](https://github.com/FujiwaraChoki/supoclip/blob/f467ff31e395f4b38c7810bc47bdd33e46313c39/backend/src/video_utils.py#L1398-L1406), [synthetic timing](https://github.com/FujiwaraChoki/supoclip/blob/f467ff31e395f4b38c7810bc47bdd33e46313c39/backend/src/video_utils.py#L1447-L1516), [fallback/iteration boundaries](https://github.com/FujiwaraChoki/supoclip/blob/f467ff31e395f4b38c7810bc47bdd33e46313c39/backend/src/video_utils.py#L1097-L1118).

## Detached related projects worth distinguishing from forks

**cspenn/supoclip**, `main`, [`bd332926af8d2b7cb39a8f3f6de882e20d53c734`](https://github.com/cspenn/supoclip/tree/bd332926af8d2b7cb39a8f3f6de882e20d53c734), is currently a standalone repository (`fork=false`). This contains the substantial Apple local rewrite; the separate listed `cspenn/supoclip-local-mlx` fork remains at old commit `cb0e0afc83c7ea5715bec4ead1606368fd477e9b` with AssemblyAI code and is not the feature-bearing repository. [Old fork source](https://github.com/cspenn/supoclip-local-mlx/blob/cb0e0afc83c7ea5715bec4ead1606368fd477e9b/backend/src/video_utils.py). The rewrite actually calls Parakeet MLX, transcribes in 120-second chunks with 15-second overlap, merges subword tokens and caches word timings. It also implements VLM active-speaker selection/engagement scoring/thumbnail selection behind feature flags. It uses a different `src/pipeline` structure and SQLite-oriented local app. Treat it as an algorithm/reference donor, not a current web-app merge candidate. [Transcriber](https://github.com/cspenn/supoclip/blob/bd332926af8d2b7cb39a8f3f6de882e20d53c734/src/pipeline/transcribe.py#L269-L319), [vision implementation](https://github.com/cspenn/supoclip/blob/bd332926af8d2b7cb39a8f3f6de882e20d53c734/src/pipeline/vision.py), [config flags](https://github.com/cspenn/supoclip/blob/bd332926af8d2b7cb39a8f3f6de882e20d53c734/src/config.py).

**nugiwabot/supoclip**, `main`, [`1c1671f2be39e3c6dc5e5137663ee9376de0c64d`](https://github.com/nugiwabot/supoclip/tree/1c1671f2be39e3c6dc5e5137663ee9376de0c64d), is also a standalone repository (`fork=false`). ## Facebook and live/archive findings: bounded conclusion

No Facebook publisher was found in the source-inspected candidates above. Current upstream Instagram implementation explicitly uses Instagram Login and does not require a linked Facebook Page; Meta/Instagram credentials alone do not constitute Facebook support. [Instagram provider](https://github.com/FujiwaraChoki/supoclip/blob/e42e93b02873d29e2000a6a8235c10e23f8c99c9/backend/src/social/instagram.py#L1-L12).

None of the verified GPU/local donors supplies the complete live-session archive layer requested for the project: persistent session/chunk records, retained originals, absolute stream timestamps, overlap/deduplication, capture recovery and publish policy still need to be integrated. Speech chunk overlap in the Parakeet implementation is an ASR technique applied to a completed video file, not an archive controller for a running live broadcast.
