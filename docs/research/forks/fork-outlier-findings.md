# SupoClip capped-diff and unrelated-history outliers

Research date: 2026-11-16. The figures below describe the initial outlier pass; [the final aggregate](summary.md) includes three subsequently enumerated descendant forks. This closes the filename-coverage gap left by GitHub's 300-file compare response limit. The network inventory has 728 listed forks, 722 reachable forks, 11,328 branch references and 615 distinct heads; 261 are outside current upstream history. Fifteen heads needed this follow-up: ten capped comparisons and five with no common ancestor.

Full recursive Git trees were enumerated for all fifteen exact heads, independent of the compare API. Application source and documentation were searched for live capture, streamlink, rclone, Facebook publishing, local/GPU speech, hardware encoding, backup and social integration signals; matching implementation paths were read. Committed virtual environments and bundled agent framework files were excluded from product capability searches. No repository scripts, installations, live credentials or GPU/media benchmarks were executed.

## Result

No additional complete live-session recorder/archive controller or rclone integration was found. The two substantive extra references are **RyanSquad's ElevenLabs adapter** and **Aspirewastaken's old social/backup/hardware-encoding rewrite**. Neither changes the recommendation to integrate selected modules into current upstream.

“Archive” requires care: RyanSquad's archive is a ZIP download of generated clips; Aspirewastaken backs up existing upload/clip directories and database records. Neither supplies persistent live session/chunk recording, absolute stream timestamps, capture recovery, overlap deduplication and retained originals. “Facebook” also requires care: an Instagram request to graph.facebook.com and an analytics platform label are not Facebook publishing.

## Source-backed exceptions and integration limits

**RyanSquad**: `backend/src/media/transcription.py` implements ElevenLabs request/word normalization/cache conversion and dispatch with Whisper fallback (roughly lines 319–579). This is a hosted provider adapter, not GPU/local speech acceleration. [Immutable adapter](https://github.com/RyanSquad/supoclip/blob/53aaa28502c60023ccfe6d3a6ed6d15b715eb1da/backend/src/media/transcription.py). Its `stream_source.py` states “Live streams aren't supported” and rejects live URLs, while `clip_archive.py` streams generated clips into ZIP. [Downloader](https://github.com/RyanSquad/supoclip/blob/53aaa28502c60023ccfe6d3a6ed6d15b715eb1da/backend/src/stream_source.py), [ZIP export](https://github.com/RyanSquad/supoclip/blob/53aaa28502c60023ccfe6d3a6ed6d15b715eb1da/backend/src/clip_archive.py).

**Aspirewastaken** has substantive code, not just advertising: platform enum TikTok/Instagram/YouTube/Twitter; OAuth and video upload implementations; scheduled-post/attempt records; a Redis queue and APScheduler worker. However, the OAuth callback explicitly creates a placeholder `platform_user_id` rather than fetching the actual platform identity. OAuth state is regenerated using the current timestamp, so verification does not establish a robust stored callback state. Instagram requires a caller-supplied public `video_url`. These are concrete source gaps, sufficient to reject treating the whole fork as a ready-made publisher. There is no Facebook platform implementation. [Social implementation](https://github.com/Aspirewastaken/supoclip/blob/9ef89b68c7b7ddf9e61dae7520a25a30cc423085/backend/src/integrations/social_media.py), [callback placeholder](https://github.com/Aspirewastaken/supoclip/blob/9ef89b68c7b7ddf9e61dae7520a25a30cc423085/backend/src/api/routes/social_media.py#L217-L220), [posting scheduler](https://github.com/Aspirewastaken/supoclip/blob/9ef89b68c7b7ddf9e61dae7520a25a30cc423085/backend/src/integrations/scheduler.py).

Its backup code recursively copies existing uploads/clips and writes metadata, with local/S3/B2 backends and scheduled DB/file backup. This is useful disaster-recovery reference material, not live capture. [File backup](https://github.com/Aspirewastaken/supoclip/blob/9ef89b68c7b7ddf9e61dae7520a25a30cc423085/backend/src/backup/file_backup.py), [storage configuration](https://github.com/Aspirewastaken/supoclip/blob/9ef89b68c7b7ddf9e61dae7520a25a30cc423085/backend/src/backup/config.py).

Its hardware encode path detects NVIDIA NVENC, Intel QSV and AMD AMF, selects codec parameters, and passes those settings into MoviePy `write_videofile`. This is a genuine additional encoding donor, with high adaptation cost from its old monolithic architecture. Availability probing and source wiring do not establish successful GPU encoding or caption performance. [Encoder settings](https://github.com/Aspirewastaken/supoclip/blob/9ef89b68c7b7ddf9e61dae7520a25a30cc423085/backend/src/utils/performance.py#L250), [render integration](https://github.com/Aspirewastaken/supoclip/blob/9ef89b68c7b7ddf9e61dae7520a25a30cc423085/backend/src/video_utils.py#L775).

**bychrisr** social and Facebook search results are competitor analysis and future work: both scheduler and direct-posting stories have unchecked implementation tasks. Its transcription service is a hosted Gemini→AssemblyAI path. [Scheduler story](https://github.com/bychrisr/supoclip/blob/a603cd3df1ce6edc6f52b10fd458fcbec5415510/docs/stories/story-features-social-scheduler.md), [posting story](https://github.com/bychrisr/supoclip/blob/a603cd3df1ce6edc6f52b10fd458fcbec5415510/docs/stories/story-features-direct-posting.md), [transcription](https://github.com/bychrisr/supoclip/blob/a603cd3df1ce6edc6f52b10fd458fcbec5415510/backend/src/services/transcription_service.py).

**NT995 and DoubleRRL** are rewrites rather than mergeable modular extensions, and their inspected speech code calls AssemblyAI. [NT995 service](https://github.com/NT995/supoclip/blob/2244352491d7e1bbbb24c6fd4d00ba89e68ffb16/backend/src/modules/transcription/transcription.service.ts), [DoubleRRL transcript module](https://github.com/DoubleRRL/cliptime/blob/e43f07a0f3fd11f5ec6796affed27e48735781a2/backend/src/video_transcript.py).

## Coverage limits

This is exhaustive over visible branch-head inventory and the fifteen outlier trees, not every historical commit, tag, deleted/private branch, detached non-fork repository or running deployment. Six enumerated forks were inaccessible. All conclusions about missing capabilities are bounded to this source screen. No code was executed to prove service/API correctness, backup restoration, platform approval, GPU throughput or media quality.
